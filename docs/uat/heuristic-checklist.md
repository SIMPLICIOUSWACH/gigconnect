# Heuristic evaluation checklist

The proposal applies Nielsen's (1994) ten usability heuristics to every screen. Each evaluator goes through the screens
on their own, writes down every problem they find under the heuristic it breaks, and gives it a severity. Then the
evaluators merge their lists and agree one severity per problem.

## Severity

| Rating | Meaning |
|---|---|
| 0 | Not a usability problem |
| 1 | Cosmetic: fix if there is time |
| 2 | Minor: low priority |
| 3 | Major: important to fix |
| 4 | Catastrophe: must be fixed before release |

## The heuristics, in short

1. **Visibility of system status.** The user always knows what is going on (loading, saved, sent, failed).
2. **Match between the system and the real world.** Words and order the user would use, not system terms.
3. **User control and freedom.** A clear way out of a mistake: cancel, undo, go back.
4. **Consistency and standards.** The same thing looks and works the same everywhere.
5. **Error prevention.** The design stops mistakes before they happen (confirmations, sensible limits).
6. **Recognition rather than recall.** Options and information are visible, not to be remembered.
7. **Flexibility and efficiency of use.** Quick for experienced users without confusing new ones.
8. **Aesthetic and minimalist design.** Nothing on screen that competes with what matters.
9. **Help users recognise, diagnose and recover from errors.** Plain error messages that say what to do.
10. **Help and documentation.** Help is easy to find when it is needed.
